# Structural equality

Use `structurallyEquals(...)` when the entire query is the contract. Declare the
expected SQL directly; whitespace, ordinary comments, keyword case, and an optional
trailing semicolon do not affect the comparison.

```java
var userPage = Expect.sql(POSTGRESQL)
    .as("user page structure")
    .structurallyEquals("""
        SELECT id, name
        FROM users
        WHERE active = true
        ORDER BY id
        LIMIT 20 OFFSET 40
        """)
    .build();

// The same structure with different formatting and keyword case passes.
userPage.assertMatches("select id, name from users where active = TRUE order by id limit 20 offset 40;");

// A changed page size is a structural mismatch.
var result = userPage.evaluate("SELECT id, name FROM users WHERE active = true ORDER BY id LIMIT 10 OFFSET 40");
System.out.println(result.describe());
```

Output:

```text
[user page structure] SQL did not match expectations:
- [STRUCTURE_MISMATCH] Expected SQL <LIMIT 20 OFFSET 40> but was <LIMIT 10 OFFSET 40>.
```

Calling `userPage.assertMatches(...)` with the changed query throws an
`AssertionError` containing that same diagnostic. Identifier spelling and quoting,
aliases, projection order, predicates, literals, and parameter names remain
significant. This compares parsed structure, not semantic equivalence. Use focused
checks such as `table(...)` or `leftJoinTable(...)` when other query changes should
remain acceptable.

For SQL generated by application code, see the
[complete-query showcase](https://github.com/icher-g/assert-sql/blob/main/assert-sql-examples/src/test/java/io/assertsql/examples/CustomBuilderExampleTest.java).
