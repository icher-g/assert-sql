# Assert SQL 0.1.0

First release of Assert SQL: declarative assertions for SQL structure without executing queries.

## Included

- Immutable, reusable expectations with assertion-framework-independent results and standard `AssertionError` failures.
- Checks for statement kinds, tables, columns, joins, projections, predicates, grouping, ordering, pagination, and parameters.
- Complete-query structural comparison that ignores formatting and keyword case.
- Query scopes for outer queries, CTEs, derived tables, and EXISTS subqueries.
- Explicit binding assertions and complete parameter coverage checks.
- Statement collection assertions for query counts and unexpected statements.
- Structured diagnostics, expectation descriptions, and configurable value redaction.
- Optional validation against caller-supplied in-memory catalogs.
- Runnable jOOQ and Hibernate/H2 examples.

Uses SQM 0.5.1 with ANSI, PostgreSQL, MySQL, SQL Server, and Oracle parsers. Includes regression coverage for Hibernate compact equality,
jOOQ parenthesized AND predicates, and set-query ordering/pagination.

## Installation

Requires JDK 21+. After publication to Maven Central, add:

```xml
<dependency>
    <groupId>io.github.icher-g</groupId>
    <artifactId>assert-sql-core</artifactId>
    <version>0.1.0</version>
    <scope>test</scope>
</dependency>
```

For catalog validation, use `assert-sql-validation` at the same version; it includes core transitively.
No additional Maven repository or credentials are needed for Central releases.

## Boundaries

Assertions inspect parsed SQL structure; they do not prove semantic equivalence, runtime results, tenant isolation, or query performance.
Parser support depends on the selected SQM dialect. See the [compatibility guide](../wiki/Compatibility.md) for remaining limitations.
Anonymous binding positions follow SQM traversal order and may differ from JDBC bind order.
